# 人物聊天室 Tab 与 3D 圆桌交互设计

日期：2026 年 10 月 10 日。状态：首版设计草案，尚未实现界面。所属任务：[T16](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/16-roundtable-chat-ui.md)。

## 入口与页面结构

新增与“林间图书馆”并列的“人物聊天室”Tab，导航 key 为 book-rooms，路由建议 /book-rooms，选中房间可使用 /book-rooms/:roomId。刷新、前进后退均能回到同一房间；没有 roomId 时展示最近房间与“创建聊天室”。房间只属于当前工作区。

图书馆书目详情保留“与人物对话”和“加入聊天室”快捷入口。选择人物后打开新 Tab 中的创建表单或已有房间；进入场景、点击人物、切换房间和旋转相机均不自动调用模型。房间切换器放在顶部，可用弹层展开列表，不常驻第三栏。

桌面默认左侧为 3D 场景，右侧为完整对话栏；右栏初始宽度 400px，可在 360–560px 范围拖动调整，剩余宽度给场景。在可用内容宽度小于 960px 时改为上下布局或“场景 / 对话”切换，优先保留输入和完整消息。

```text
┌ 人物聊天室 · 房间切换 ▾  [+ 创建] [添加人物] [房间设置] ───┐
│                         │ 当前轮：2/5 · 剩余 48 秒        │
│    人物 B      人物 C    │ A ·《书甲》                    │
│      ○ ┌──────┐ ○       │ “刚才你提到的事情……”            │
│        │ 圆桌 │         │ B ·《书乙》                    │
│      ○ └──────┘ ○       │ “在我的经历里……”                │
│    人物 A      人物 D    │ [查看依据] [跳到最新消息]       │
│   ↳ A 的头顶发言气泡     ├───────────────────────────────┤
│                         │ [自动选人] [@ 人物] [@ 全体]   │
│ [全景] [缩放] [人物列表] │ 输入问题……              [发送] │
└─────────────────────────┴───────────────────────────────┘
```

右栏依次为本轮状态和队列控制、消息历史、输入栏。倒计时使用本窗口的服务端秒数快照；“设置”快捷入口打开已实现的时间配置。顶部新增“自由聊天 / 主题聊天”切换，主题模式显示可编辑主题和可选目标；它决定讨论范围，输入栏的自动选人、指定人物和全体提问决定回应者，沿用既定有限轮次策略。详见[理论复核与模式设计](F:/god/project/Octopus/docs/plans/book-character-agents/agent-design-review.md)。忙时不换题，切换不发送消息、不改变座位。T17 完成前只展示自由聊天默认态，不假称已启用主题模式。

## 场景与角色外观

参考现有[林间图书馆渲染器](F:/god/project/Octopus/frontend/src/pages/Knowledge/library/scene/LibrarySceneCanvas.jsx)：Babylon.js、圆形木桌与软垫椅、暖木及石灰色板、植物、暖光和环绕相机。其 readingNook 已有圆桌椅，thinkerStatue 已有程序化坐姿人体；将合适的基础构件提取为共享构件，分别组合阅读区与聊天室场景。

首版是一张木质圆桌，所有在场人物坐于各自座位，身体朝向桌心。环境留出头顶气泡空间，减少书架和植被遮挡。默认相机采用略俯视的三分之四视角，可旋转、缩放、恢复全景；点击角色可聚焦，自动跟随发言者默认关闭，用户拖动期间不抢镜头。

角色采用可复用的简化坐姿模型，用衣饰色、名牌和书籍标签区别成员。原著没有外貌依据时使用中性外观；首版不增加自动生成头像或真实人物模型任务。模型外观是展示资产，不成为原著事实。情绪或动作仅展示公开发言的表现，不把人物私有心理材料变成所有角色可见的信息。

| 人物状态 | 场景表现 | 对话栏表现 |
| --- | --- | --- |
| 空闲 / 排队 | 正常坐姿；排队徽标可见 | 等待用户或队列位置 |
| 正在生成 / 校验 | 名牌高亮，头顶“正在回应…” / “正在校验…” | 同成员占位状态，无候选正文 |
| 已发布 | 短暂发言高亮，头顶展示对应消息 | 同 message_id 的完整正文与依据 |
| 禁言 | 保留座位和人物，明确禁言图标 | 可阅读；@ 发送前提示不可发言 |
| 仅 @ 回应 | 名牌标记“仅 @” | 可选为定向目标，自然模式不选中 |
| 已移除 | 原座位变为空椅，名牌标记已离场 | 历史保留，可从成员管理重新加入 |
| 来源失效 | 空椅及“来源失效”标记 | 历史可读，此成员不能继续生成 |
| 本轮暂停 / 失败 | 清除正在生成气泡和动作 | 显示原因、继续或停止，不制造人物正文 |

点击角色或名牌打开同一成员操作卡：查看公开档案、@ 该人物、仅 @ 模式、禁言/解禁和移除。选择 @ 只填入目标，不自动发送。读者私密依据在独立详情中查看，不能进入多人场景的公开状态或人物上下文。成员列表提供相同操作，键盘和触屏无需精确点击 3D 模型。

## 座位与房间数据

book_rooms 增加 scene_layout_version（首版为 1）与 scene_capacity（默认 8）。创建多人房间时按实际成员数向上取 8 的倍数；book_room_members 增加 seat_index，整数从 0 开始，且 UNIQUE(room_id,seat_index)。服务端分配座位，客户端不能按姓名、消息序号或列表顺序重新编号。

scene_layout_version 固定布局算法，seat_index 与 scene_capacity 决定圆周位置及朝向：角度为起始角加 2π × seat_index / scene_capacity，桌面半径按容量与椅间距计算。位置是前端推导值，不逐帧写入数据库。座位序号不参与原著权限、消息先后或发言公平性。

座位与 member_id 在房间内保持绑定。刷新、断线恢复、禁言、移除后重返、清空记忆均保留位置；移除时保留空椅，不立即压缩座位。新成员使用未分配的座位，不能复用仍有身份记录的离场座位。容量不足时，只有房间没有 queued/running/paused/interrupted 轮次才允许扩容；扩容与加入同一事务完成，页面提示桌面已扩展。不会在一轮发言中重新排座。

人数增加时仍为一个圆桌，按容量增加桌径，提供全景与人物列表快速聚焦。远处可降低模型细节；这只影响渲染，不能截断成员名单或全体队列。大量角色时允许用户主动切换为二维座位/成员视图，全部角色仍属于同一个房间。首版不提供拖拽换座。

## 气泡与对话生成同步

气泡是公开消息的场景投影，右侧对话栏是完整记录。两者由同一个 useBookRoom 状态管理，不能各自订阅并追加一套消息。

1. 本轮为人物分配槽位后，显示对应成员“正在回应…”；生成和校验期间不显示原始 token。
2. CharacterReplyValidator 通过后，服务端原子写入消息与引用，再广播 message_published。正文包含 message_id、room_id、epoch、seq、speaker_member_id、round_id 和 slot_id。
3. 客户端根据 message_id 去重，以 seq 补齐和排序；同一次状态更新创建右侧消息和该人物气泡。默认对已发布内容做短暂逐字呈现，共享同一个 reveal_cursor；点击或开启减少动态效果时立即显示全部。
4. 展示动画不延迟数据库发布、他人读取或下一槽位执行。它只是已校验文本的视觉效果；首版不提供未校验 token 流。后续如实现真正分段流式输出，需逐段通过权限与语义校验后才可公开。
5. 每个人物头顶只保留其最近一条当前会话实时发言，正文建议至多 120 字或 3 行，其余以“…”收起，点击跳转右侧完整消息。停止渐显后默认保留 8 秒再淡出；悬停、键盘聚焦或点击固定时暂停消失。同一人物新消息替换旧气泡，历史文本仍在右栏。
6. 首次加载和重连补拉历史消息不自动重播全部气泡；只恢复当前生成状态。用户点击历史消息可临时定位角色并显示对应历史气泡，标记“历史消息”，不会触发生成。

头顶位置用角色的 head_anchor 投影到屏幕，在 canvas 上方用 React DOM 渲染气泡，支持中文排版、选中、点击与无障碍阅读。气泡本体面向用户，无需把每次文字变化绘制为 3D 纹理。相机或容器变化时更新投影，遵循设备像素比与 CSS 像素转换；视野外隐藏或显示边缘指示，不钉在错误位置。

气泡重叠时优先展示当前发言者与用户选中的角色，再显示最近消息，其他气泡折叠为可点开图标。单轮只允许一个槽位生成；前几名人物的已发布气泡可短暂同时保留。视觉重叠不会影响消息投递。

## 事件、停止与恢复

useBookRoom 保存权威 RoomSnapshot、成员、当前轮次及按 seq 排序的已发布消息。BookRoomScene 只接受公开投影 RoomSceneState；renderer 只拥有相机和 GPU 资源，不能持有模型上下文或决定谁可以发言。

book_room get 返回成员的 seat_index、房间 scene_layout_version 与 scene_capacity。场景投影包括 member_id、seat_index、公开身份、在场/发言模式、当前槽位和公开消息引用。progress 事件带 epoch、round_id、slot_id、lease_generation、execution_window 和相关成员的 membership_generation，不包含候选正文。跨书房间没有全局 build_id；需要原著身份时由对应成员附带来源元组。

进度事件作为刷新提示，通过串行合并的 get 拉取最新快照；过时请求结果按工作区、房间与请求代数丢弃，状态快照与消息补拉统一应用。message_published 可直接按 ID/seq 合并，检测到缺号则补拉。首版不依据单个迟到的 progress 事件恢复“正在回应”。若后续直接消费进度增量，需要先实现可校验的服务端状态版本。

超时、停止、禁言、移除、来源删除、重置 epoch 和切换工作区会清理不再有效的生成占位与动画。已发布消息即使作者之后离场仍保留；历史气泡不能使已移除人物重新坐回或恢复发言。其他书的有效人物继续沿用有限队列。

切换 Tab 或房间只卸载场景，不等于停止后端轮次。右侧明确提供暂停/停止；返回房间后读取快照。路由卸载必须移除 observer、事件监听、动画定时器和 render loop，并释放 mesh、材质、纹理、scene 和 engine。

## 可访问性与性能验收

- WebGL 初始化失败或上下文丢失时显示二维成员/座位图，右侧消息、@、禁言、移除和停止仍可操作；恢复渲染不重发用户消息。
- 场景只生成一次并增量修改人物状态；消息到来不重建整个桌面。尽量共享几何和材质，静止/页面不可见时暂停或降低渲染，气泡投影只在相机、人物或容器变化时更新。
- 减少动态效果时取消相机补间、角色待机与逐字/淡出动画；消息通过右侧可访问日志播报一次，气泡不重复播报。
- 操作验收覆盖 1、4、8、16、32 人、相机遮挡、气泡重叠、长中文消息、窄屏、禁言移除、局部来源删除、暂停继续、重连和反复切换房间；记录设备、帧率与 GPU 资源释放情况，不预先承诺固定性能。
- 场景展示和完整队列分别验收，3D 成功不代表原著权限或调度已经通过。生产代码实现与构建验收由 T16/T12 完成。
