# 保留失败单元并继续独立来源扫描

## 原因与实现

此前发现工作器两次失败后立即停止整部书，其余几百个未处理单元也无法前进；自动恢复还会把所有失败单元尝试数清零。按详细设计“仍失败的单元记录错误”和检查点约束，本次将后续独立工作与显式失败重试分开。

- 发现工作器每单元仍最多两次。耗尽者保留failed及原结果/错误，继续其他attempts<2单元。没有剩余可运行单元时，只要还有失败，构建在同一fence事务内标为发现失败；只有全部成功才discovery_complete，T03及自动流程不会提前提取或发布。
- 中断恢复只重排尚未接受的运行尝试，保留次数；第二次中断也不获得第三次调用。已耗尽的发现、档案及表达单元不被恢复自动重置。显式retry保留原有重新尝试能力，已验收检查点不改。
- 新增`continue_auto_import`，只在当前discovery流程确有未处理单元时排队，不重试终止失败。计数限定书籍、来源、B、资料项与有效生命周期；协议要求工作区及当前任务身份，仍使用原控制锁、授权检查和代数撤销。功能关闭时禁止写入。
- 界面分别提供“继续未处理单元”和原来的重试/新版本；人物面板显示保留失败数量，不将失败计入完成覆盖。

失败前新增回归复现首单元阻塞尾部、第二次中断后的后续工作丢失。新文件8项覆盖尾部推进、终态失败不进T03、显式重试只补失败且不改成功哈希、恢复不清尝试数、真实WS排队/错误工作区/重复排队、缺失身份和禁用门控。相关四模块36项通过；此前核心与自动模块的23项/14项属于开发中专项，不与完整项目相加。

两轴审查无阻塞：组合绑定、两次上限、档案/表达恢复、终态原子性与界面/协议一致性保持。Mypy限定55文件（`--follow-imports=skip`）、Ruff、相关组件ESLint、前端类型检查与生产构建通过；保留既有chunk体积/循环及动态静态混用警告。
