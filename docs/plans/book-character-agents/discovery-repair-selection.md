# 发现修复的原文编号选择

2026-10-14，沿用 T02 的候选、有限重试和来源约束；不增加原著授权或用户操作。

v11 的真实修复仍会重写引文标点或用当前场景没有的全名，导致两次调用后整单元失败。继续要求模型复制原文容易重复该错误；模糊接受或自动改写引文可能掩盖错误来源。因此 v12 保留首次发现，在已有第二次修复中让模型选择服务器给出的原文编号。

## 处理规则

1. 首次发现仍按原结构验证。结构冲突、无可用选项或输入过大时，继续原来的完整第二次生成，不增加调用次数。
2. 只为失败条目列出其场景内的字面称呼和精确原文窗口，每目标至多 8 个选项。服务器固定 segment ID、码点范围及文本，模型输入只含当前目标的选项，不给其他场景原文重写。
3. 原有未歧义别名可用于保持已知身份；其他字面短称只是候选表面词，不能证明同一身份。选择这些词只能以服务器分配的新键建立 uncertain/id=null 待复核人物，不自动挂接旧人物。代词选项只建立未具名 unknown/uncertain 候选。
4. 回复只含目标坐标、保留/不确定、在场类型、原文编号与额外别名编号。不能提交自由引文、任意人物 ID 或局部身份键。额外别名限已给出的别名候选；不确定身份不能增加别名关系，同名冗余别名不再重复构造第二份引文。
5. 原文编号只在目标内有效；缺失、重复目标、未知编号、未提供的身份保持或别名均拒绝。服务器组装完整条目后，仍通过原有完整单元校验及发布事务的来源/租约检查。已通过条目保持不变，取消或删除不接收迟到结果。

## 上下文与失败

只发送原名/状态、错误和原文选项，投影的 UTF-8 JSON 上限 6000 字节。先保证每目标一个选项，再轮流加入可选项；移除的编号也从内部允许集移除。最小投影仍超限则回退完整第二次生成，不丢目标。

修复包仍属于含原文的检查点，由现有来源删除清理。新提示版本创建新构建，不重写 v11 的失败、模型配置或检查点。每单元仍最多两次模型调用；这个设计不能证明被选择称呼就是同一人物，也不能替代 T03/T12 的身份与原著质量复核。

## 验证

生产服务回归覆盖精确原文组装、合法条目不变、未知编号、取消和删除；纯函数检查其他场景原文不进入选项、新称呼不能保持旧身份、错误主体/别名/目标/重复补丁拒绝，以及输入预算和保留集一致。复用 v11 两个实际失败单元做固定预算修复，再进行新版本全来源窗口；合同通过和人物质量分别记录。
