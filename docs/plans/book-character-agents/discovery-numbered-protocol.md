# v13 人物发现紧凑编号协议

首版全书运行仍在发现阶段失败。已观察到重复既有身份、跨场景绑定和引文中的未转义引号；完整重生成又会损坏合法条目。v12 的第二次原文编号修复保留，但首次生成改为编号协议，避免反复生成 UUID、原文和偏移。

## 约束与投影

服务器在当前单元中固定片段编号、原文窗口编号及已给人物编号。原文窗口最多384码点，相邻长窗重叠80码点，引用只映射到同单元的精确片段/范围；不作模糊引文或名字补全。模型读取这些原文数据，不执行其中的指令。

人物注册表每个局部身份只声明一次 new/existing/uncertain、匿名与实体类型。场景仅引用注册号，按有序片段编号覆盖整个单元；每次出现分别给当前称呼、在场类型、原文编号和别名编号。既有身份优先使用给定 names 的编号；也接受字面名字进入原完整校验，名字不在原允许别名中必须拒绝/有限修复，不自动改名或挂旧 ID。n/kn 不能并给，新/不确定身份不能用 kn；匿名缺展示标签时使用服务器未具名标签，实体仍 unknown/待复核。注册表不能重复既有人物编号，场景不能重复局部身份；未用注册、陌生编号、错误场景引用和字段错配均拒绝。

服务器扩展为既有 DiscoveryResult，再通过未放宽的完整原文/身份校验与发布事务。编号仅减少传输冗余，不证明身份、在场或知情，更不授予原著知识。原文窗口可能含旁白，仅用于发现及读者定位；T03/T05 仍独立审查人物实际获知和安全引文。

模型读取完整编号窗口；字面名字在该窗口唯一出现时，存储引用只保留名字及左右各至多12码点的精确上下文，偏移由服务器固定，避免同窗多人物展开重复超出原100000字符上限。不是唯一出现、匿名或没有匹配名字时不裁剪，仍按完整原文检查。场景及原片段保持完整，不以裁剪授予在场或知情；必要容量保留原30场景×80条目，不能偷偷删人。

重复称呼可显式给出该称呼在窗口内的0起出现号 `o`，再定位精确上下文；越界或无名字的次数号拒绝，缺少o不猜第一次。这样密集名单仍可用精确短引文表达原容量；展开依然超过100000时明确失败并有限重试，不删候选或放宽上限。

## 失败与版本

本版本仍每单元最多两次调用。已可扩展但未通过的条目进入原有有限定点/编号修复；语法、注册或分组不可恢复时，第二次完整编号生成，不跳过或删除失败条目。取消/删除/重启继续检查原授权与租约代数。

新任务使用 v13，新配置指纹创建独立构建；不覆盖或拼接 v12 的有效/失败检查点。固定旧失败单元的原生 v13 试验与新全来源窗口分别报告。不得把紧凑输出、契约通过或样本重放当作全书人格验收。

## v14 场景内窗口修复

新解析配置使用 v14，v13 仍按原协议恢复。原字面选项不足时，只把失败目标交给第二次窗口修复；窗口按场景限制，n/e/o由同一个精确跨度解析器展开，保留身份只可用原已给名字；uncertain必须换独立键并清旧ID。修复仍覆盖每个目标恰好一次，合法条目保持，组装后经原完整校验与发布栅栏。窗口输入上限16000字节，超限不删目标/截断原文，仍有限完整重生成。

v14 可省已有身份的n/kn，但只有选定原文窗口内恰好存在该身份一个已给名字才还原；零个/多个都拒绝，不猜身份、别名或其他窗口。此还原不授予原著知识。行为、预算与实际失败见[阶段验证](validation/2026-10-15-window-repair-validation.md)。
