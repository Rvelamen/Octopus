# T08 创建跨书多人房间并进行定向与自然回应

状态：已完成存储、服务、协议与界面链路及阶段验收（2026 年 10 月 14 日）。阶段：M3。完整模型质量由 T12 验收。

## 用户可见交付

用户从不同书籍选择人物，点名或让系统选择相关人物顺序回应；各角色能回应公共交流，同时保留自己的原著范围。

## 前置依赖

[T07 保留房间记忆并支持独立重置](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/07-room-memory.md)。

## 实施步骤

1. 扩展房间来源与成员管理，验证每个成员属于自己登记的来源构建。
2. 支持 directed 与 natural 发言方式，点名用 ID 解析，自动选人结合公开人物信息、话题及发言公平性。讨论方式 free/topic 由 T17 扩展，规划不能读取私有材料。
3. 单房间顺序运行，每名人物独立取证和组装上下文。
4. 消息显示人物身份与回复对象；忙时禁止新增来源或成员，禁言和移除立即生效。固定公开成员/消息快照，供 T16 的圆桌和右栏共用。

## 验收标准

- [x] 指定人物回复正确，名字相同也不会串角色。
- [x] 自然模式默认至多三人，单轮结束后不会自动无限互聊。
- [x] 后发言者可回应前面的公共内容，但不能读取其他人物私有依据。
- [x] 各人物的人设与知识范围独立。
- [x] 所有可用人物均可加入名单，稀疏人物可选择沉默。

- [x] 成员复合外键关联自身 room_source 与人物的 B，可以有不同书的构建，但不得借用其他来源授权。
- [x] 多人继续共享原著库，新增记忆按房间与代数隔离，不建立全体共享私有知识。

- [x] 可从不同书籍的已发布构建选择成员，明确列出 room_source；每房每书固定一个构建。
- [x] 同名角色使用 member_id 和书籍标签定向 @，不按显示名称猜测身份。
- [x] 支持 auto、mention_only、muted 和移除；mute 后仍在场但包括 @ 在内均不能发言。
- [x] 运行中禁言或移除立即递增 membership_generation，撤销该成员未发布槽位，不影响其他成员。

- [x] 已发布消息明确包含 message_id/seq/speaker_member_id，生成和校验进度不广播候选正文；圆桌展示不扩大人物知识范围。

## 验证场景

- 不同角色收到不同上下文的多轮集成样本。
- 定向多人、自然选人、公平性和忙时成员修改。
- 秘密公开后的听说传播与私有材料隔离。

- 房间构建与成员构建不一致、私有知识与公开听说区分。

- 两部书成员混聊、同书第二构建冲突、同名 @ 和未登记来源成员拒绝。
- 禁言后 @ 不回应、mention_only 只接受定向或全体邀请、解禁后旧结果丢弃。
