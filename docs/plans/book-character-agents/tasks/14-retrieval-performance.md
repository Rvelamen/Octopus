# T14 增强长书检索与控制多人调用成本

状态：首版任务草案，已同步跨书群聊与成员控制。阶段：增强。

## 用户可见交付

较长书籍和更多人物下仍能找到允许的依据，用户可查看调用量、等待时间和预算暂停原因。

## 前置依赖

[T09 向全体提问并控制可恢复的发言队列](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/09-all-participants-control.md)。

## 实施步骤

1. 实测现有中文检索召回与人物上下文大小，再接入可配置语义检索。
2. 向量候选必须在人物允许集内产生或排序，保留全文检索降级。
3. 缓存固定原著检索材料，键包含工作区、来源、构建、人物和策略版本。
4. 设置构建及房间总预算，采集阶段耗时与模型 usage，验证暂停恢复。

## 验收标准

- [ ] 增加检索路径后全部知识边界回归继续通过。
- [ ] 中文召回和延迟与既有基线可比较，不能只报告主观效果。
- [ ] 关闭向量能力仍能使用首版检索。
- [ ] 缓存失效与来源删除有效，房间消息不进入跨房间共享缓存。
- [ ] 预算暂停不会丢失剩余人物队列。

- [ ] 向量检索和缓存均使用完整人物范围，房间记忆缓存另外包含 room_id 与 epoch。
- [ ] 对范围联接和分页用查询计划实测，避免重复增加已有唯一索引覆盖的前缀索引。

- [ ] 房间缓存无单一 build_id 假设；人物缓存继续按该成员 B，消息摘要按 room_id＋epoch。

## 验证场景

- 更长来源、较多成员、允许集排序与降级。
- 缓存版本、跨房间污染、预算暂停恢复。
- 相同样本与模型配置的检索和耗时比较。

- EXPLAIN QUERY PLAN、允许集向量候选、索引同步与缓存作用域。

- 不同成员来源绑定和控制代数变化时的缓存隔离与失效。
