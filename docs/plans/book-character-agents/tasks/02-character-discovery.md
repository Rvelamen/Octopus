# T02 手动构建全书人物候选名单

状态：首版任务草案，已同步存储约束。阶段：M1。

## 用户可见交付

用户点击构建人物，看到全书人物候选、别名与待消歧状态，任务进度可查询。

## 前置依赖

[T01 在书目中准备可定位的全文来源](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/01-narrative-source.md)。

## 实施步骤

1. 建立构建记录、场景、人物和检查点，服务端固定来源与工作区。
2. 按场景执行人物发现与对白归属，处理跨场景别名候选。
3. 加入后台工作器、有限模型调用和结构化结果校验，阶段失败可重试。
4. 提供构建查询与名单分页，在书目人物页显示处理量和身份冲突。

## 验收标准

- [ ] 构建覆盖全部来源片段，名单不是仅来自书籍开头。
- [ ] 人物只被提及不会被默认标为场景参与者或知情者。
- [ ] 同名与称呼冲突保留待消歧状态，不强行合并。
- [ ] 候选名单阶段不显示人物已具备可用原著知识。
- [ ] 重复请求返回已有任务；处理错误有明确阶段和原因。

- [ ] 场景、人物、检查点均带 B；场景片段同时校验来源和构建。
- [ ] 别名和参与者使用关系表，同名别名可以标为歧义，不能做全局唯一合并。
- [ ] 重复指纹复用构建；后台连接始终绑定创建任务时的工作区。

## 验证场景

- 记录输入的模型替身验证只读取当前来源。
- 别名、同名、匿名人物、仅提及人物与对白说话者不明样本。
- 重复构建请求与单场景模型格式失败重试。

- 跨来源场景片段、同名歧义、构建指纹和连接范围检查。

## 完成记录

实施时记录实际改动、检查命令、演示结果和未通过项。模型质量与确定性的权限检查分别记录，不把模型替身测试当成真实模型评测。
