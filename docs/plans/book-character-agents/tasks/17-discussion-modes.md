# T17 支持主题聊天与自由聊天

状态：首版任务草案，尚未实施。阶段：M3。

## 用户可见交付

用户可在同一人物圆桌中自由聊天，或设置跨轮保留的主题与讨论目标。两种讨论方式都可自动选人、@ 人物或 @全体，原著约束及有限轮次保持有效。

## 前置依赖

[T08 创建跨书多人房间并进行定向与自然回应](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/08-multi-character-room.md)。

配置、快照和主题/free 基础流程可用 T08 的定向/自然接口验收。T09 的全体与恢复、T16 的圆桌入口随后联调，整合验收归 T12；两者不阻止先落实本任务的基础契约。

## 实施步骤

1. 迁移 rooms 的讨论方式、主题、目标、revision；旧房间默认 free。新增 rounds 的 discussion_snapshot_json；历史轮次回填默认 free，不能猜测原主题。
2. 实现 set_discussion 的 epoch/revision 检查、内容长度校验与 room_busy 保护。新轮次从服务端房间配置取得快照，和更新配置互斥，恢复仍使用原快照。
3. 将讨论方式和发言方式分开；主题进入本人允许集的相关性排序和上下文，不增加任何原著或外部知识权限。
4. free 根据最新问题和公共对话组织回应；topic 保留主题与可选目标，允许不同观点，偏题作轻量提示。未知话题可询问或进行有据推演。
5. 在现有房间操作界面提供切换/编辑与当前快照状态，在 T16 圆桌顶部复用；操作不自动生成。T09 完成后联调全体和恢复。
6. 增加用户主动的公共总结，保留说话者、分歧和听说类型；暂停继续与“再讨论一轮”是不同操作。
7. 验证六种模式组合、模型知识诱导、人格目标与情绪触发，记录主题相关性及过度拒答。

## 验收标准

- [ ] free/topic 与 natural/directed/all 是独立两层，API 和 UI 不混用同一 mode 参数。
- [ ] topic 要求非空主题；free 清空主题和目标；长度与 revision 非法时完整拒绝更新。
- [ ] 配置只在无活跃轮次时切换，旧窗口结果不能使用新主题发布；暂停恢复保留原讨论快照。
- [ ] 切换模式/换题保留房间成员、座位、epoch 和原著基线，不自动新建模型调用。
- [ ] 自由聊天可转换话题，主题聊天跨轮保留主题；合理的情境推演不会因原书没有该问题原句而全部拒绝。
- [ ] 主持人选人只使用公开信息，主题不能使任何人物知道旁白秘密或其他书的私有事实。
- [ ] 用户讲述的书外材料归为房间听说，不能变为人物自传经历。
- [ ] 两种方式都遵守每轮每人一次、秒数窗口、成员控制和用户停止；无自动续轮。
- [ ] 总结基于同 room_id/epoch 的已发布公共消息，归属与分歧可复核，不能回写原著。
- [ ] 基础流程在 T08 上可独立验收，全体/恢复/圆桌联调结果在 T12 完成记录中补齐。

## 验证场景

- free/topic × natural/directed/all；默认 free、空主题、主题编辑版本竞争、运行/暂停中换题拒绝。
- 长中文主题与目标、旧客户端兼容、断线、恢复及显式再讨论一轮。
- 主题外问题、主题指令注入、原著秘密、现代知识与跨书材料诱导。
- 同一道价值两难题的改述与多轮追问；情绪触发证据不足、失败生成不落情绪状态。
- 临时库迁移、真实服务请求/权限测试、前端构建和界面操作；真实模型质量另做人工复核。
