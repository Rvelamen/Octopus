# T11 处理书籍版本更换与删除后的房间状态

状态：首版任务草案，已同步跨书群聊与成员控制。阶段：M4。

## 用户可见交付

新版本产生新人物构建，旧房间各来源绑定固定旧版本；删除某书后只停用该书人物，其他来源有效时继续混聊。

## 前置依赖

[T04 纠正人物身份与依据并发布修订版本](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/04-evidence-corrections.md)；[T09 向全体提问并控制可恢复的发言队列](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/09-all-participants-control.md)；[T10 导入小说后自动构建人物并恢复后台任务](F:/god/project/Octopus/docs/plans/book-character-agents/tasks/10-automatic-import-build.md)。

## 实施步骤

1. 将来源、构建、缓存和房间的版本关系贯穿导入与修订。
2. 新版本通过新建房间使用，旧房间不自动替换人物。
3. 删除来源时取消任务、失效检索和缓存、清理原著材料，保留聊天显示名快照。
4. 对应来源与成员显示失效；仍有有效来源时保持混聊，全部来源失效时转只读；工作区切换清除过期状态。
5. 服务关闭时停止工作器、释放租约和关闭连接。

## 验收标准

- [ ] 不同译本和新版证据不能混用，旧引用不会错指新片段。
- [ ] 删除某来源后其人物不能发布迟到回复，其他有效来源人物仍可发布。
- [ ] 已有消息仍显示人物名字和来源已删除状态。
- [ ] 不同工作区的同名书目和相同局部 ID 不会串数据。
- [ ] 正常关闭与异常重启行为一致可解释。

- [ ] 保留 book_id、source_version_id、build_id 和 character_id 的身份关联，不置空房间归属。
- [ ] 清理原文、知识、可见证据、候选检查点和可能包含原文的错误详情，历史快照只供显示。
- [ ] 数据库先禁用，版本文件后清理；清理失败可重试且不能恢复人物回复。

- [ ] 删除某书只停用对应 room_source 与成员，其余来源有效时保持房间 active。
- [ ] 其他书角色已开始的请求及槽位不因局部删除被整轮取消；最后可用来源失效时才全房只读。

## 验证场景

- 重导入同版、新版、人物修订与旧房间读取。
- 删除与生成竞争、缓存失效和引用不可用。
- 工作区切换、生命周期停止与数据连接释放。

- 来源清理后身份外键仍完整、候选材料清空与旧消息可读。

- 混聊房间局部来源删除后其他角色继续发言，全部来源删除后只读。
