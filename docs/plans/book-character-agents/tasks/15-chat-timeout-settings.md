# T15 配置人物聊天室时间上限并持久化

状态：设置界面及持久化已实现并验证。阶段：设置。

## 用户可见交付

用户在“设置 → 图书馆 → 人物聊天室”配置普通轮次和全体提问的时间上限，单位秒，可保存、刷新回读并恢复默认。

## 前置依赖

无，可独立开始。T06 的轮次创建与基本超时处理依赖本任务。

## 实施步骤

1. 在全局 agent_defaults 添加普通时间上限与全体时间上限，默认 60 秒和 300 秒；按已有迁移模式兼容旧数据库。
2. 贯穿 Record、Repository、配置 schema、agent_defaults_get/update 的字段映射，缺失字段不覆盖已保存值。
3. 在设置页增加正整数秒输入、单位说明、保存与恢复默认，先验证再写入任何配置。
4. 后端严格验证整数、正值和可存储可执行范围，拒绝空值、小数、负值、0、布尔及无限值，保存失败保留旧配置。
5. 提供按 directed/natural 与 all 读取所需秒数的接口，T06 与 T09 在新执行窗口启动时读取快照。

## 验收标准

- [x] 普通轮次初始 60 秒，全体提问初始 300 秒，界面明确显示单位秒。
- [x] 用户可自定义正整数秒，保存后刷新和重启仍能正确回读。
- [x] 旧客户端未提供新字段时保留现值，旧数据库升级后有正确默认值。
- [x] 非法输入在前后端均被拒绝，不能以 0 或空值取消上限，不能影响其他设置。
- [x] 恢复默认同时恢复 60/300 秒，并清楚区分修改与保存。
- [x] 设置提示新轮次或手动继续时生效，进行中的执行窗口不随修改改变。
- [x] 全局偏好与工作区人物及聊天室数据的存储位置保持分离。

## 验证场景

- 旧数据库迁移、默认值读取、两字段保存回读与部分字段更新。
- 空值、布尔、小数、负数、0、超出支持整数范围，以及非法保存的原值保持。
- 前端加载、修改、保存、恢复默认、重新打开设置。
- normal/direct 模式与 all 模式选择正确字段，运行中快照保持旧值。
- 实施时记录真实检查命令；SQL 草案校验不代替设置页和真实 API 测试。
