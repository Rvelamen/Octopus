# Octopus 书籍人物 Agent 与多人聊天室研究

研究日期：2026 年 10 月 10 日。适用范围：工程现有图书馆、知识库，以及从一本书自动建立人物并进行多人对话的能力。

建议在图书馆上增加书籍人物数据层、人物专属检索和聊天室调度。现有工程可复用书目管理、后台任务、模型配置、WebSocket 和聊天界面，但人物的知情范围、信念、情感依据和多人消息身份需要新增结构。最关键的质量标准是：人物说出的内容符合其在原著中的视角，表达和反应能追溯到书中证据。

已确认两项用户选择：人物可以使用全书中自己亲历或获知的内容，不按读者阅读进度限制；人物记住本聊天室的对话，同时保持原著事实与核心人设固定。聊天室记忆按房间隔离，不能写回原著依据或传播到其他房间。

## 关键结论

1. **功能有研究基础，但自动构建质量仍需验证。** BookWorld 已研究从小说构建人物与世界并组织多人物互动；其官方仓库同时明确提示自动抽取代码不稳定。对 Octopus 而言，应该吸收其人物和调度的分工，并建立独立的抽取校验流程。[1](https://aclanthology.org/2025.acl-long.773/)、[2](https://github.com/alienet1109/BookWorld)
2. **全书检索不足以实现人物视角。** 2026 年的 ReverieMem 研究将人物经历、带可见性标记的事实和情境化表达分开，直接针对人物知道原著中自己不该知道的事实的问题。它是本需求最贴近的记忆设计参考，但属于预印本，且没有专门的多人调度机制。[3](https://arxiv.org/html/2606.25632v1)
3. **人物的原著依据与新对话必须分开存储。** 这是针对用户约束的工程设计建议：新的聊天可以产生当前房间的记忆和反应，但不能反向成为原著事实或覆盖人物设定。
4. **每个人物可以是逻辑 Agent，共享模型。** 各自的身份、证据范围、人物状态和房间记忆构成独立实例，模型仅在需要发言时调用。首版适合采用这种方式。

## 现有流程中的具体缺口

### 解析尚未面向长篇人物叙事

PDF 提取代码将 section 写为空，跳过少于 20 个字符的段落，并以空格分词数量记录 token_count。这对短对白、章节和中文长度估计都有影响。扫描 PDF 的空文本页会被跳过，该函数没有 OCR 路径。首版应优先处理可提取文本的书籍，识别空文本和缺页；需要 OCR 时进入明确的处理状态。

[get_item_chunks](F:/god/project/Octopus/backend/services/library_engine.py:1522) 默认最多读取 100 个片段。人物抽取必须遍历全文，使用分页或迭代接口，并校验实际处理片段数，防止只构建书籍前半部分的人物。

### 当前范围限制不能保证人物隔离

[ScopedLibrarySearchTool](F:/god/project/Octopus/backend/agent/library_chat_agent.py:82) 先全局取 limit 的两倍结果，再按路径前缀过滤。目标书目可能在全局排名之外，导致过滤后没有结果；scope_paths 为空时也不会执行过滤。新检索应在数据库查询阶段应用 book_id、版本和人物权限，再排序与限制数量；人物范围为空时返回无可用依据。

限制路径的提示词不能替代工具检查。[LibraryReadNoteTool](F:/god/project/Octopus/backend/tools/library_knowledge.py:119) 根据传入路径读取文件，没有人物范围参数；[ReadFileTool](F:/god/project/Octopus/backend/tools/filesystem.py:82) 也支持通用文件路径。人物 Agent 应只使用经过范围检查的原著证据接口。

[LibraryChatAgent 的默认工具](F:/god/project/Octopus/backend/agent/library_chat_agent.py:343) 包括全局 memory_search 和 memory_read；[工具配置](F:/god/project/Octopus/backend/agent/library_chat_agent.py:408) 还可以启用执行命令、写文件等能力。新人物的工具白名单应服务于原著读取与本房间记忆，不继承个人全局记忆、网络访问或通用文件执行能力。

### 摘要蒸馏会引入其他书目

[knowledge_task_worker.py](F:/god/project/Octopus/backend/services/knowledge_task_worker.py:137) 的图书馆分支面向论文摘要，要求检索相关笔记并添加跨论文链接。这个流程适合知识关联，但人物设定只能从当前原著构建。人物抽取需要单独的任务类型、提示词和工具范围，不能只替换用户 prompt。

### 中文检索需要额外处理

当前片段索引采用 unicode61 分词。使用同样配置的内存 SQLite 小实验，将“张三来到客栈。李四在读书。”写入索引后，得到以下结果：

| 查询 | 命中数量 |
| --- | --- |
| 张三 | 0 |
| 客栈 | 0 |
| 张三来到客栈 | 1 |

这个实验仅证明该样本下短词检索的缺口，不代表对整套工程的召回率评估。建议结合中文别名字段、经过验证的分词或字符检索，以及语义检索；所有检索路线先执行人物可见性筛选，再融合和排序。

### 工作流知识服务仍是占位实现

[KnowledgeService.search](F:/god/project/Octopus/backend/services/knowledge_service.py:15) 直接返回空列表。它是工作流数据集搜索的占位服务，不能作为已具备语义 RAG 的依据，也不代表实际的笔记索引引擎没有工作。

## 原著限定的具体语义

### 读者知道的事实与人物相信的内容

至少应分别保存世界事实、人物信念和证据。事实是否真实、人物是否知道、人物是否相信、人物是否愿意公开，是不同的问题。

以下是虚构示例，用来说明数据区别：

| 原著内容 | 甲可用的记忆或信念 | 乙可用的记忆或信念 |
| --- | --- | --- |
| 旁白说明乙撒了谎，但甲没有发现 | 甲相信乙的说法 | 乙知道自己撒谎 |
| 甲误以为丙背叛了自己 | 保存甲的误解及其依据 | 乙是否知道，需要另外的原文证据 |
| 后续剧情中甲收到证明并改变态度 | 保存信念修正与情感变化 | 不自动同步给乙 |

全书可用表示取消章节截止条件，仍需逐人物确认获知路径。人物死亡或最后退场后发生的事，也不能自动成为其记忆。聊天室可采用书外会面的形式，让不同时期出现的人物共处，而各自使用最后有证据支持的状态。

不能因为人物在同一场景出现，就默认其看见所有细节；睡着、离开、未听清都会影响知情。同组织成员之间的信息传播也需要实际交流或明确共同背景的证据。遇到不可靠叙述者或相互矛盾的回忆，应保留各自的叙述来源和冲突状态，不能自动合并成唯一真相。

### 人生观和情感需要保留解释依据

人物档案应记录价值取舍、动机、关系态度、典型反应和表达样本，每项附原文位置与解释强度。书中直述、多个行为支持的解释和证据不足的推测应有不同状态。模型给出的 confidence 只能作为候选排序信号，不能当作事实正确概率。

不要将人物压缩为“冷静”“勇敢”等单一标签。保留人物在冲突、亲近、受挫等不同情境中的原著表现，以及随剧情变化的立场。默认以最后有明确依据的状态作为对话基线，旧状态保留为历史；无法确定最终状态时展示不确定性。

人物可以针对新提问产生符合原著的反应。这种新反应属于基于原著的模拟，不能标为原书中实际发生过的情感或对白。如果用户要求每一项情绪都必须是书中直接记载，则应采用更严格的访谈模式，并允许人物对无依据情境表示无法判断。

### 全部人物与证据稀疏程度

自动识别应覆盖全书出现的具名人物及可区分的匿名角色，合并有依据的别名，避免把所有“他”或相同称呼误合并。主角和仅出现一次的人物都可以有档案，但档案状态应区分完整、证据稀疏、待消歧和构建失败。

证据稀疏人物在对话中可以保持简短、表达未知；系统不能为了让每个人都能流畅长谈而补造经历、价值观和情绪。可由用户纠正名称与合并关系，新增设定应明确属于用户扩展，严格原著模式不使用它。

## 三条实现路线比较

| 路线 | 内容 | 优点 | 代价与适用范围 |
| --- | --- | --- | --- |
| 人物证据库与受限检索，推荐 | 结构化原著数据、人物可见记忆、共享模型、独立聊天室调度 | 对每本新书生效，证据可审查，适合现有工程 | 需要完善解析、抽取、检索与验收 |
| 人物提示词与全书摘要 | 给每个人物生成角色卡，在聊天时注入全书摘要 | 最快验证用户是否喜欢交互 | 容易出现全知人物、扁平情绪和互相串人格，适合作为短期体验样例 |
| 角色训练与持续世界模拟 | 训练角色表达，运行长期目标、关系和环境演化 | 后续可探索复杂叙事和长期演绎 | 数据与评价成本更高；原著证据权限仍然必需，适合后续阶段 |

首版建议选择第一条路线。先证明人物能在适当场合准确说出自己知道的内容，也能对不知道的事保持未知，再扩大自动构建和群聊规模。

## 建议的数据与模块边界

以下是工程方案建议，并非已实现接口。

| 模块 | 职责 | 输入与输出 |
| --- | --- | --- |
| 书籍解析 | 全文、章节、场景及稳定定位 | 附件版本 → 可定位的原文段与场景 |
| 人物构建 | 人物发现、别名、对白归属、事件和人物档案 | 原文场景 → 有出处的候选数据 |
| 证据校验 | 检查引用存在、支持关系、冲突与知情路径 | 候选数据 → 可用、未知、冲突或待复核数据 |
| 人物存储 | 保存人物、信念、关系及版本 | 已校验数据 → 人物专属视图 |
| 人物检索 | 按书籍版本与人物权限取依据 | 服务端绑定身份和提问 → 有权限的记忆与表达样本 |
| 人物运行时 | 根据人设、依据和房间消息产生候选回复 | 私有上下文 → 发言及事实依据 |
| 聊天室调度 | 管理参与者、顺序、回复目标和终止 | 用户消息与房间状态 → 有限的发言任务 |
| 输出校验 | 检查新增事实、人物身份与可见性 | 候选回复 → 发布、重写或未知回复 |

建议继续使用 SQLite 保存结构化记录，Markdown 保存便于阅读的人物档案。初期无需为了实体关系单独部署图数据库；语义检索组件的选择依据书籍规模、中文召回和模型环境再决定。

每个人物作为书籍绑定的持久化 Agent，关联人物档案与模型配置模板，进入房间后再创建其会话状态。可以复用现有角色配置的模型字段，但应以书籍人物类别管理，避免自动把几百个人物加入通用任务助手列表。多人发言共享模型服务，各自构造上下文。

数据结构至少需要以下概念：

| 概念 | 必要信息 |
| --- | --- |
| 书籍版本 | book_id、内容哈希、解析器版本、构建版本、任务状态 |
| 原文位置 | segment_id、章节、页码或 EPUB 定位、原文偏移、文本哈希 |
| 人物与别名 | character_id、book_version_id、名称、别名及合并证据 |
| 事件 | 场景、参与者、叙事顺序、故事时间及原文出处 |
| 事实与可见性 | 命题、事实状态、人物获知方式、获知事件及出处 |
| 人物信念 | belief_owner、相信的命题、依据、修正关系、最后支持状态 |
| 表达与情感依据 | 情境、触发、反应、对白样本、解释状态及出处 |
| 房间与成员 | room_id、固定的书籍构建版本、成员与各自人物状态 |
| 发言与房间记忆 | speaker_character_id、reply_to、可见范围、原著依据、房间依据 |

叙事顺序与故事内时间必须分开，避免倒叙被当成新事件。每个人物的历史和最终状态也应分别保存。

## 导入后自动构建的流程

1. **导入并建立书籍版本。** 保存原文件与哈希；同一版本避免重复构建，版本不同的译本和改编不能混用。
2. **检查文本质量。** 检测空文本、缺页、重复页眉和编码异常，保留段落对白。章节不可靠时允许回到可定位文本分段。
3. **遍历全文建立场景。** 每段必须有稳定来源位置；为人物抽取保留邻近上下文，同时记录实际处理范围。
4. **发现人物并处理指代。** 先建立候选名单，逐场景补充别名和对白归属，再合并跨场景实体。无法确定的归属暂留未知。
5. **抽取经历、信念、关系与反应。** 基于场景提取候选项并保留原文证据；原著中没有的内容不能由外部资料补全。
6. **校验人物获知路径。** 亲历、观察、被告知和共同背景分别保存证据。只被提及的人物不自动成为事件知情者。
7. **生成各人物的受限记忆与档案。** 档案分为可公开简介和运行时私有材料，避免把秘密直接放入所有人的角色列表。
8. **发布构建结果。** 展示人物名单、证据覆盖和失败阶段；支持更正与重试，已有书籍阅读和普通问答仍可继续使用。

任务建议具备分阶段检查点与幂等性，按原文哈希和构建版本复用已完成场景。书籍版本更换后，旧聊天室保留原版本，用户选择后才切换人物；删除来源时同步失效其构建材料和检索缓存。

不建议一次性用一个长 prompt 处理整本书，也不建议让每个人物独立重读全文。共同抽取场景与候选事实后，再按人物建立视图，可以控制重复处理量并定位抽取错误。

## 人物对话与多人调度

### 每次发言的上下文

每个人物的上下文由固定的人物身份、原著依据、本房间可见消息和当前反应状态组成。服务端绑定 book_version_id、character_id 与 room_id，模型不能通过参数改成另一人物身份获取材料。

先在受限记忆中寻找相关经历，再取有获知证据的事实和该人物的表达样本。原始场景可能同时包含旁白秘密和其他人物心理；不能因为场景中有人物，就把完整场景直接送入其上下文。用户查看引用可以看到原文，人物运行时使用经过校验的视角材料与允许读取的原文片段。

生成后，对具体原著事实要求可用证据，对假设性回答标记其推演性质。无依据时用人物的口吻表达未知或保留意见。工具过滤可以阻止检索越界，但不能消除模型预训练知识，因此仍需要输出校验与专门的越界测试；LLM 校验器本身也会犯错，不能承诺所有自由文本绝对符合原著。

人物公开表达可以包含原著支持的隐瞒或谎言。系统内部应记录它与事实的关系，不能把人物撒谎直接当成生成错误，也不能让其他人物读取其私有动机。

### 原著记忆与聊天室记忆

建议至少区分三类信息：原著依据、房间内听到的说法，以及对新问题的模拟推演。原著依据由书籍构建产生，聊天不会更新它。

当甲在公共房间说出自己知道的秘密，乙可以记住“甲刚刚如此说”，但不能因此声称“我在原著里亲眼见过”。公开说法可在房间内传播，私聊只给可见成员；对话摘要也要保留说话者、信息类型和可见范围，避免摘要把听说升级成事实。

按已确认的选择，房间对话可以影响当下的语气和短暂情绪，但不覆盖原著价值观、人物经历和原著中的关系状态。人物可以记得本房间发生的交流，并在后续回应中引用；新房间从原著人物基线开始，不继承其他房间的交流。重置房间记忆只清除本房间的交流记录与派生状态，原著依据保持不变。

### 轮次与成员

默认所有已生成的人物都在可选名单中，用户可选择活跃成员。定向提问由被点名人物回复；未点名时由调度器结合话题、关系和近期发言选择少量人物，允许某个人物沉默或退出本轮。

“所有人物可对话”不意味着每次输入都要让全员同时回答。用户明确向全体提问时，应按队列覆盖全体，允许跳过无话可说者并显示进度，不能悄悄只选几个角色。预算不足时暂停并保留队列，轮次数量和自动互动都应有上限。

首版建议按顺序生成发言。前一个人的已发布消息成为后一个人的可见上下文，能够支持真正的回应。调度器可以访问人物索引和公开关系以选人，但不把全书秘密、其他人物的私有记忆或完整内部状态传给发言者。

消息需要保留人物身份、回复目标、原著引用与房间引用。来源说明可以折叠在“依据”面板中，日常对话保持自然。后台校验过程中显示人物正在回应，校验通过后才发布；提前把原始 token 直接推送给用户，会让越界内容在校验前出现。

### 界面入口

建议在书目详情增加“人物”和“聊天室”入口。导入时可选择自动构建人物，默认行为在产品确认后确定；构建进度单独显示。人物卡片展示身份、关系、典型表达和证据状态，点击依据跳转到原文位置。

聊天室显示人物名单、当前回复者、定向提问和全体提问入口，并提供停止、继续与重置房间记忆。对找不到依据和构建失败的状态给出明确反馈，避免看起来所有人物都已具备完整知识。

## 分阶段交付与验收

| 阶段 | 可审阅的产物 | 验收重点 |
| --- | --- | --- |
| 书籍构建基础 | 一本文本可提取的小说、完整人物名单、主要人物证据档案 | 全文覆盖、别名和对白归属、来源定位、重试与版本一致性 |
| 单人物对话 | 若干主要人物可单独对话，稀疏人物明确未知 | 知道的能回答，不知道的不补造，误解与修正符合原著 |
| 多人物聊天室 | 选人、点名、全体队列、顺序回应和停止 | 身份正确、回复有关联、私有信息不串用、对话不无限延续 |
| 自动构建与质量扩展 | 导入触发构建、更多格式与书籍、缓存和回归样本 | 中文召回、长书覆盖、成本、长期人格和知识边界 |

首个验收样本建议选择有明确人际关系与信息差、文本完整的一部小说，抽查 3 至 5 个主要人物，同时检验次要人物名单与未知表达。无需为第一轮实验生成图片、配音或地图。

验收集应由读过原书的人复核，并覆盖以下情况：

| 类型 | 期望行为 |
| --- | --- |
| 亲历与明确被告知 | 人物正确回答，并能定位对应依据 |
| 旁白秘密与他人内心 | 人物不因全书模型知识而直接确认 |
| 错误信念与后续修正 | 人物使用最后有证据支持的信念，解释自己的变化 |
| 原著支持的隐瞒 | 表达符合人物动机，内部不把谎言登记为世界事实 |
| 原著未涉及的现代事物 | 不凭空声明原著经历，可表达不了解或进行有边界的类比 |
| 新的价值冲突情境 | 反应能关联原著取舍，推演不伪装成原书情节 |
| 公共消息与私聊 | 听说来源清楚，私聊内容不传给其他人物 |
| 多轮诱导与错误前提 | 不接受用户对原著事实的随意改写 |
| 全体提问、超时与停止 | 队列状态可见，终止有效，已发布消息保持一致 |
| 重新导入与版本切换 | 引用不会错指新版片段，旧房间可继续追溯 |

质量指标应分别记录可知事实回答正确率、不可知事实拒答率、无依据原著断言比例、人格与情感一致性，以及多人回复关联性。只有拒绝率高也不合格，否则所有人物都回答不知道即可获得虚假的边界成绩。阈值应在选定书籍、模型和人工标注样本后建立，当前不预填未经验证的达标数字。

成本主要来自一次性书籍构建和每轮实际发言的人物数量。粗略计算方式是：构建输入输出量加上发言人数乘以每次检索、生成与校验的消耗。具体费用与延迟需用用户实际模型配置测量；首版通过共享场景抽取、缓存人物材料、限制自动轮次和按需调用降低重复工作。

## 已确认的产品边界与后续选择

已确定全书人物知识范围，以及记住本聊天室对话、固定原著事实与核心人设的记忆规则。后续需要确定对新情境的情感表达是否接受有原著依据的推演，以及默认人物状态是否使用最后有证据支持的阶段。这些选择不会改变人物专属证据库和房间记忆隔离的必要性。

另需选定首个试验书籍及其格式，并用其中的信息差评估自动抽取。对于非虚构作品，应另外区分真实人物、作者与观点代理；不能把作品中的一种观点直接当作完整人物人格。
